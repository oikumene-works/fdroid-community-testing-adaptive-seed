# Fictional Image Mop Walkthrough

This example demonstrates the complete record shape without identifying,
downloading, installing, or posting about a real application. Every service
identifier and digest is synthetic, URLs use reserved `example.invalid`, and
`EXAMPLE_ONLY=true` makes guarded action scripts refuse the case.

Run `./scripts/fictional-dry-run.sh` for an offline executable walkthrough of
the denial gates. It creates and removes only an ignored-local fixture.

## 1. Selection

The fictional candidate differs from a timer/reminder example because its
primary path copies synthetic text-image fixtures into an output folder. The
record rejects accounts, payments, networking, sensitive permissions, and
physical-device use.

## 2. Source and claim preflight

`case.md` pins the imagined MR/build/source mapping and defines a bounded test.
`claims.md` compares the fictional listing's “input is never changed” statement
with the imagined copy-only source path. The review is marked `PASS` only for
the fictional snapshot.

## 3. Built-APK qualification

`qualification.md` shows the fields that an approved download-inspect-delete
slice would produce. No APK exists, and no parser was run for this example.
The `PASS` value illustrates a later gate but grants no authorization.

## 4. Execution and cleanup

The imagined checklist uses only synthetic files and a disposable emulator.
The example report explicitly says execution was not performed. A real case
would need fresh exact-download and emulator approvals, target verification,
runtime observations, uninstall, wipe verification, and evidence deletion.

## 5. Report and posting

The sample `report.md` is a dry-run record, and `public-comment.md` is visibly
non-postable. A real report is reviewed after cleanup; a comment then needs a
separate exact digest, destination, account, and live-state approval.
