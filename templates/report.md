# Bounded Functional Test Report

**DRAFT — NOT APPROVED FOR PUBLIC POSTING**

Record executor, human involvement, date, exact MR/pipeline/job/source, app
version, APK and certificate digests, AVD/API/build identity, locale/timezone,
and one carefully scoped result.

## Timeline and duration

Use machine-generated UTC milestones with actor and result. Separate selection,
preflight, operator waiting, visible execution, cleanup, report preparation,
total active work, and end-to-end elapsed time.

## Public claim review

Record claim-surface/review digests, gate status, and material limitations.

## Basic and policy-facing observations

Record only checked facts about launch, language, permissions, denial behavior,
accounts, terms, payments, advertising, tracking, and external navigation.

## Functional coverage and limitations

Map every planned item to one allowed result and provide evidence:

| Planned checklist item | Result | Concrete observation or limitation |
| --- | --- | --- |
| Replace with one bounded item | Pass / Partial / Not tested / Inconclusive | Replace with exact evidence |

Do not omit an item because it was unsupported or stopped. Do not infer a
general security or acceptance result.

## Final package inspection and cleanup

Record package/version/SDK/permission/certificate state, crash/ANR checks,
uninstall, wipe verification, stop, artifact deletion, and upload state.

## Public comment

Keep exact public text in `public-comment.md`. Posting needs separate approval
of the file digest, destination, and account. A later immutable full-report
link is a new reviewed mutation.
